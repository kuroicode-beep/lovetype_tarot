## 우선순위별 발견사항

### 1. [P1] 서버 충전 API가 영수증 검증 없이 잔액을 올림

근거: `C:/Projects/lovetype-api/src/routes/v1.js:311-369`, `src/index.js:17-23`.

`/payment/charge`는 `app_id`, `user_id`, `product_id`만 요구한다. `receipt`는 길이 로그만 남기고 검증하지 않으며, 인증 사용자와 지갑 소유자를 연결하는 검사 및 거래 ID 중복 차단도 이 경로에 없다. 모형 호출에서 인증·영수증이 없는 동일 요청이 두 차례 모두 200으로 처리되고 잔액이 10→20으로 증가했다. 미등록 상품에도 요청의 `amount`를 포인트로 인정하는 경로가 있다.

영수증의 스토어 검증, 검증된 상품별 지급액, 인증 주체의 지갑 귀속, 거래 단위 중복 차단을 서버에서 보장해야 한다. 이는 로컬 소스 재현 결과이며 운영 서버에서 취약성을 시험하지 않았다.

### 2. [P1] 앱·서버 쿨타임 조회 인자가 달라 항상 사용 가능으로 보일 수 있음

근거: `lib/services/api_service.dart:117-124`, `C:/Projects/lovetype-api/src/routes/v1.js:186-194`.

앱은 `topic=daily/romance`, `category_key=today/love`를 보내지만 서버는 `theme`만 읽는다. `theme`이 없으면 DB 조회 전에 `available: true`를 반환한다. 방금 리딩한 사용자 모형에서도 앱 인자는 대기 0초, `theme=daily`는 대기 3600초를 반환했다. `/tarot` 생성 경로에도 별도 쿨타임 검사가 없다. 클라이언트 인자 정합과 생성 시점의 서버 검사가 함께 필요하다.

### 3. [P1] 충전 검증 실패 뒤에도 구매 완료 처리·진행 상태 제거

근거: `lib/services/iap_service.dart:137-175`, `179-211`.

`_sendReceiptToBackend`가 예외를 잡고 정상 반환하므로, 충전 API가 실패해도 호출자는 `completePurchase`와 `_clearPending`을 실행한다. 영수증의 영속 재시도 큐도 없다. 재시작 시 `_pendingUser`가 없으면 구매 완료 이벤트의 서버 전송도 건너뛴다. 실제 결제 후 포인트 미지급을 앱이 복구하기 어려운 흐름이다. 서버 지급 확인과 스토어 완료 처리를 분리하고, 거래·사용자 정보를 재시작 후에도 복구할 수 있어야 한다.

### 4. [P1] 실제 인증 없이 닉네임으로 지갑·히스토리 식별

근거: `lib/screens/intro_screen.dart:57-72`, `lib/services/storage_service.dart:113-115`, `lib/services/auth_service.dart:15-21`.

Google·전화번호 시작 버튼이 모두 정보입력 화면으로 바로 이동한다. `AuthService.signIn`, `ApiService.authGoogle`, `setBearerToken`, `setGoogleUserId`의 실제 로그인 호출부가 없다. 따라서 `local_닉네임`이 히스토리·결제 사용자 ID로 쓰이고 같은 닉네임은 같은 ID가 된다. 실제 인증과 서버 소유권 검증을 먼저 연결해야 한다. `authGoogle` 메서드 본문에도 현재 서버가 필수로 요구하는 `app_id`가 없다.

### 5. [P2] 고대비 모드와 최소 글자 크기 규칙 미충족

근거: `lib/core/theme.dart:8-16,96,124`, `lib/screens/result_screen.dart:540`, `lib/screens/card_confirm_screen.dart:184,207,235`, `lib/screens/card_draw_screen.dart:421`, `lib/screens/info_input_screen.dart:295`.

10~11 크기 글자가 8곳 있다. `textMuted=#6B5D80`의 대비는 기본 배경에서 약 3.05:1, 카드 배경에서 약 2.57:1이다. 화면에서 `AppTheme.textMuted` 등의 색을 직접 지정해 고대비 테마의 흰색이 적용되지 않는 곳도 있다. LINESeedKR 글꼴 선언·번들도 pubspec에서 확인되지 않았다. 공통 테마 참조와 최소 12 크기 적용을 함께 정리할 필요가 있다. 실제 기기 시각·스크린리더 평가는 별도다.

### 6. [P2] 히스토리 재전송 중 새로 추가된 대기 항목 유실 가능

근거: `lib/services/history_sync_service.dart:72-85`, `lib/services/storage_service.dart:141-156`.

`flushPending`이 읽어 둔 큐를 네트워크 작업 뒤 실패 항목만으로 덮어쓴다. 그 사이 `uploadReading`이 새 항목을 적재하면 마지막 덮어쓰기에서 빠질 수 있다. 자동 저장 실패 후 저장 버튼을 누를 때 같은 리딩을 다시 적재하는 중복 경로도 있다. 거래와 별개로 리딩의 고유 ID와 큐 갱신 직렬화가 필요하다. 이 항목은 코드 경로 분석 결과이며 동시성 실행 재현은 하지 않았다.
