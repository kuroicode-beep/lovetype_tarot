## 결과

앱 `0.2.0+2`의 로컬 검증 후보를 만들었다. 이전 스토어 문서 6개를 기존 커밋 `c0a48a1` 그대로 master에 통합하고, 인증·결제·쿨타임·구매 복구·히스토리 큐·접근성을 수정했다. 운영 API는 출시 전 비용 방지를 위해 중지된 기록과 현재 Railway 상태를 확인했으므로 재기동하지 않았다. 이 결과는 실서비스 출시 완료가 아니다.

## 적용 순서

1. Flutter 3.47.2 / Dart 3.13.2에 맞춰 패키지 설정을 재생성했다. 기존 단위 테스트 17개가 정상 실행됐다. 공유 SDK는 수정·업그레이드하지 않았다.
2. Google 로그인과 서버 사용자 검증을 연결했다. 인증 전 화면 이동과 `local_닉네임` 지갑 식별을 제거하고, 만료 시 토큰 재갱신·로그아웃·계정 표시 캐시 분리를 추가했다. 토큰은 영구 저장하지 않는다.
3. 서버가 Google Play 상품/구독의 계정·상태·상품·만료를 검증한 뒤 지급하도록 했다. 임의 amount fallback을 제거하고 영수증 해시의 고유 제약으로 재시도 중복 지급을 막았다. 지급 commit 뒤 소비·승인을 수행한다.
4. 앱 구매는 자동 소비를 끄고 영수증을 암호화 저장소에 먼저 남긴다. 실패·재시작 후 해당 사용자 건만 재시도하고, 서버가 승인하지 않으면 스토어 완료 처리를 하지 않는다. Android 스토어 완료는 서버에서 수행한다. 설정에 구매 복원 메뉴와 스토어 실제 가격 표시를 연결했다.
5. 문서의 `topic` 쿨타임 조회를 서버가 읽게 했고, 사용자별 PostgreSQL 트랜잭션 안에서 쿨타임·잔액 확인, 리딩 생성·저장·차감·다음 쿨타임을 묶었다. 같은 `request_id`는 기존 결과를 반환한다. 앱의 별도 차감과 서버 `/payment/use`는 중복 차감을 막기 위해 제거/차단했다.
6. 히스토리 재전송은 고유 키와 큐 갱신 직렬화로 중복·덮어쓰기 유실을 막았다. 다른 계정의 과거 대기 데이터는 보존하며 임의로 귀속시키지 않는다.
7. LINESeedKR 정본 2개를 로컬 번들에 넣고 라이선스를 함께 포함했다. 낮은 대비 글자색을 고대비 색으로 교체하고 12 미만 글자 크기 8곳을 없앴다. 선택 라벨과 일부 터치 영역을 보완했다. 로고·하단에 버전을 표시하고 설정에 업데이트 히스토리를 추가했다.

## 아직 끝나지 않은 항목

1. Google OAuth 웹 클라이언트 ID와 앱 설정, Play 개발자 계정·상품·테스터·Publisher 권한이 필요하다. 앱의 `GOOGLE_WEB_CLIENT_ID`와 서버 `GOOGLE_CLIENT_ID`를 맞추고 `PLAY_PACKAGE_NAME`, `PLAY_SERVICE_ACCOUNT_JSON`을 설정한 뒤 실제 계정 검증을 해야 한다. 현재 검증용 AAB는 이 미설정 상태를 성공으로 우회하지 않는다. 실제 후보는 `tools/build_store_candidate.ps1`로 설정을 포함해 다시 만든다.
2. 서버는 의도적 중지 상태다. 계정 준비와 서비스 재개 판단 이후 DB 백업·추가 마이그레이션·새 앱 동시 적용·실제 API 재검증이 필요하다. `/health`의 단순 HTTP 200을 실제 타로 API 정상으로 판정하지 않았다.
3. PostgreSQL의 실제 동시 트랜잭션, 기기 결제·재시작·복원·알림과 스크린리더 실측은 미검증이다. 서버 테스트는 pg-mem이라 advisory lock을 대체했으며 실제 DB 동시성 증거가 아니다.
4. iOS 영수증 검증은 미구현으로 fail-closed 상태이며, 구독 갱신·환불 RTDN 연동도 남아 있다. Firebase도 기존 placeholder 상태다.
5. Firebase Admin 계열 의존성 감사의 moderate 8건과 Gradle/AGP/Kotlin 향후 지원 경고는 남아 있다. 강제 주요 버전 업그레이드로 숨기지 않았다.
